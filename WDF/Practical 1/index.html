Synora Academic Student Portal — Problem Statement, Requirements, 15-Page Sitemap, Wireframes & Git Setup

🎯 1. Problem Statement & Objectives

Problem: Higher education students frequently suffer from schedule fragmentation where timetable changes, lecture attendance tracking (such as DEPSTAR's gross 63% lecture threshold), technical event registrations, and study resource access are scattered across disjointed notice boards and spreadsheets.

Objective: Build a unified, accessible, and responsive student academic portal for B.Tech IT Semester 3 (AY 2026–27) adhering to all 15 syllabus practicals, featuring real-time timetables, attendance monitoring, MySQL database storage, and secure role-based administration.

👥 2. User Roles & Core Requirements

Student Role
  • View today's live lecture timetable & full schedule
  • Monitor gross lecture attendance (63% threshold)
  • Browse and register for campus workshops & hackathons
  • Submit academic feedback and inquiries
  • Secure authentication and personal profile management
Administrator Role
  • View live system aggregates & KPI analytics
  • Student directory CRUD (Create, Read, Update, Delete)
  • Campus event CRUD with safe poster uploads & MIME checks
  • Real-time security and administrative audit logging
  • Role-Based Access Control (RBAC) enforcement

💡 5. Viva Preparation: URLs, Browsers & Git

Q1: What is a URL and what are its parts?
A Uniform Resource Locator locates network resources. Parts include Scheme (https://), Subdomain (portal.), Domain (charusat.ac.in), Port (:443 or :8000), Path (/pages/events.html), Query String (?category=Workshop), and Fragment (#top).
Q2: How does a browser process and render an HTML page?
1. Lexical Tokenization converts byte streams into HTML tokens. 2. DOM Construction builds node tree. 3. CSSOM Construction parses stylesheets. 4. Render Tree combines visible DOM + CSSOM nodes. 5. Reflow/Layout calculates exact pixel geometry. 6. Paint & Compositing renders pixels on GPU layers.
Q3: How are atomic Git commits maintained?
Atomic commits record single logical units of work using Conventional Commits (feat:, fix:, docs:, test:), enabling safe rollbacks and clear code audit trails.
